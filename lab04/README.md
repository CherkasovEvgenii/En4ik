## Таблица для цикла суммирования чисел 1–4

```python
total = 0
for number in range(1, 5):
    total += number
```

| Итерация | `number` | `total` до | `total` после |
| --- | --- | --- | --- |
| 1 | 1 | 0 | 1 |
| 2 | 2 | 1 | 3 |
| 3 | 3 | 3 | 6 |
| 4 | 4 | 6 | 10 |

## Почему циклы завершаются

- `for ... in range(...)` выполняется конечное число раз: `range` задаёт конечную последовательность, и цикл заканчивается, когда она исчерпана.
- В `positive_input.py` цикл `while number <= 0` читает новое число в каждой итерации. Как только пользователь вводит положительное, условие становится ложным и цикл завершается.

## Почему `range(a, b)` не всегда подходит для задания 1

- Конец `b` в `range(a, b)` не входит в последовательность, а в задании `b` нужно вывести включительно.
- При `a > b` и шаге по умолчанию (`1`) `range(a, b)` пуст, а нужен вывод по убыванию.
- При `a == b` `range(a, a)` пуст, а нужно вывести одно число.

Поэтому нужно выбирать шаг (`1` или `-1`) и границу (`b + 1` или `b - 1`) в зависимости от соотношения `a` и `b`.

## Заметки

- Максимум в `statistics.py` инициализируется первым введённым числом: при нуле для всех отрицательных чисел получился бы неверный ответ `0`.
- В `variant.py` проверка `number % 3 == 0` работает и для отрицательных чисел и для нуля. В Python остаток от деления на положительное число неотрицателен, поэтому `-12 % 3 == 0`.
- Имя `statistics.py` задано в задании, но совпадает с именем стандартного модуля `statistics`; если понадобится импортировать стандартный модуль в той же папке, файл лучше переименовать.
