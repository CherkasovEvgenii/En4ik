# Лабораторная работа №11. JSON и получение данных по HTTP

**Вариант 5: id не больше порога**

В работе реализованы чтение, валидация и анализ JSON-данных, а также HTTP-запрос к API.

### 1. Локальная обработка данных (analysis.py)
Реализована функция `validate_todos(data)` для строгой проверки структуры (типы данных, уникальность `id`, непустые строки).
Функции `completion_counts(todos)` и `top_users(counts)` вычисляют статистику выполненных задач и находят лидеров.

### 2. Индивидуальный вариант 5 (variant.py)
Функция `select_tasks(todos, user_id, parameter)` выбирает ID задач пользователя, у которых `id <= parameter`.
Для тестового набора при `user_id=5` и `parameter=2` результат: `[1, 2]`.

### 3. Запуск и сохранение (main.py)
Скрипт `main.py` считывает `todos.json`, выполняет проверки и сохраняет результаты:
* `leaders.json` — список ID задач лидеров.
* `selected.json` — результат работы индивидуального варианта.

| Файл (todos.json) | Результат (leaders.json) | Результат (selected.json) |
|---|---|---|
| 5 записей из задания | `[1, 3, 4, 5]` | `[1, 2]` (для `user_id=5`, порог `2`) |

### 4. HTTP-запрос (fetch_profile.py)
Скрипт получает данные профиля GitHub по логину и сохраняет их в `profile.json`. Обрабатывает сетевые ошибки (`URLError`, `TimeoutError`), ошибки HTTP (`HTTPError`) и неверный формат данных (`ValueError`).

### 5. Проверки (test_analysis.py)
Создан файл `test_analysis.py` с `assert`:
* Проверка успешной валидации корректного набора.
* Проверка количества завершенных задач и списка лидеров.
* Проверка индивидуального варианта: `[1, 2]` для `user_id=5`, пустой список для неизвестного пользователя.
* Проверка выброса `ValueError` при неверном типе данных.
